Every filter surface reads the same per-column config, `filterDef`, and shows the same editor:

- **Header funnel**: appears on hover, stays visible in the accent colour while the column is filtered, and opens the column's filter popover.
- **Header menu**: the column menu's Filter section.
- **Floating filter row** (`showFloatingFilters`): compact editors under the headers. Typed values filter inline; lists, trees and ranges show a summary chip that opens the full editor.
- **Sidebar Filters panel**: every filterable column, its filter summarized when collapsed.
- **Query builder** (sidebar Query panel): each condition picks a column and edits it with that column's editor.
- **Filter chips** (`showFilterChipBar`): one per active filter; clicking a chip opens its popover.

```tsx
<Grid rows={rows} columns={columns} showFilterChipBar showFloatingFilters />
```

## Choosing a column's filter

[Column types](/docs/next/columns#column-types) bring a filter that fits them: a select column filters by its options (row
counts beside each), a multi-select by any / all / none of its values, a checkbox by Yes / No, a date range by overlap, a
cascading select by tree. Set `filterDef` on a column to choose one yourself; without either a column filters as text.

| `filterDef.type` | Editor                                                                                                  | Condition                                           |
| ---------------- | ------------------------------------------------------------------------------------------------------- | --------------------------------------------------- |
| `text`           | Operator (contains, is, starts with…, is empty) + value; optional second condition (And / Or)           | `{ type: 'text', operator, value }`                 |
| `number`         | Operator (=, ≥, between…) + value(s); `stars: 5` shows a star picker                                    | `{ type: 'number', operator, value, valueTo }`      |
| `date`           | On, before, after, between, with a calendar                                                             | `{ type: 'date', operator, dateFrom, dateTo }`      |
| `select`         | Searchable checklist with counts, Select all / Clear, “(Blanks)”; `listValues` adds Any / All / None of | `{ type: 'select', values, matchMode }`             |
| `boolean`        | All · Yes · No                                                                                          | `{ type: 'boolean', value }`                        |
| `dateRange`      | Overlaps / within / includes a date                                                                     | `{ type: 'dateRange', operator, dateFrom, dateTo }` |
| `path`           | Tree checklist; a node covers everything under it                                                       | `{ type: 'path', paths }`                           |
| `custom`         | Your editor                                                                                             | anything (often a built-in condition)               |
| `none`           | No filter                                                                                               | —                                                   |

	<Tab value='From a server'>
		```typescript
		const columns: ColumnDef<Person>[] = [
			{
				field: 'assignee',
				header: 'Assignee',
				filterDef: {
					type: 'select',
					// The same loader shape as server-loaded cell editors: a page per call, searched on the server.
					async loadOptions({ search, offset, limit, signal }) {
						const res = await fetch(`/api/users?q=${encodeURIComponent(search)}&offset=${offset}&limit=${limit}`, { signal });
						const { items, total } = await res.json();
						return { options: items.map((u: any) => ({ value: u.id, label: u.name })), hasMore: offset + limit < total, total };
					},
					debounceMs: 250,
					minQueryLength: 0,
				},
			},
		];
		```
	</Tab>
	<Tab value='Custom'>
		```tsx
		const columns: ColumnDef<Person>[] = [
			{
				field: 'salary',
				header: 'Salary',
				filterDef: {
					type: 'custom',
					// A React component (or `editor`, a DOM editor). It renders on every surface.
					renderFilter: ({ filter, onChange }) => <SalaryRange filter={filter} onChange={onChange} />,
					// Emit a built-in condition and the grid matches it; for your own condition shape, add `matches`.
					summarize: (f) => (f.type === 'number' ? `≥ $${f.value}` : ''),
				},
			},
		];
		```
	</Tab>

Server-loaded lists wait `debounceMs` after typing (250 by default, through the grid's scheduler), search only past
`minQueryLength`, and keep one request in flight: a newer search waits for it, then the latest one runs. Typed text and
number filters apply after a short pause, and at once on Enter.

## Quick filter

A single search string matched across multiple columns (or every column), combined with column filters:

```typescript
api.setQuickFilter('nvda', ['symbol', 'name']); // scoped to these columns
api.setQuickFilter('nvda'); // every column
const current = api.getQuickFilter();
```

## Reading and setting filter state

```typescript
api.setFilterModel({
	team: { type: 'select', values: ['compute', 'flight'] },
	tags: { type: 'select', values: ['urgent'], matchMode: 'all' },
	salary: { type: 'number', operator: 'gte', value: 100000 },
});
api.setFilterModel(null); // clear all
```

Filters are plain objects, so they persist with the grid state and saved views, and server-side row models receive them
as they are.

## Query builder

The query model combines conditions across columns in nested AND / OR groups. Each condition holds a column and one of
the filter conditions above, matched by the same code as column filters:

```typescript
api.setQueryModel({
	version: 1,
	root: {
		kind: 'group',
		id: 'root',
		operator: 'or',
		children: [
			{ kind: 'condition', id: 'a', columnId: 'team', filter: { type: 'select', values: ['compute'] } },
			{ kind: 'condition', id: 'b', columnId: 'salary', filter: { type: 'number', operator: 'gt', value: 200000 } },
		],
	},
});
```

## Events

```typescript
import { GridEventName } from '@eregister/wit-grid-react';

api.addEventListener(GridEventName.filterChanged, () => console.log(api.getState().filterModel));
api.addEventListener(GridEventName.quickFilterChanged, () => console.log(api.getQuickFilter()));
```
