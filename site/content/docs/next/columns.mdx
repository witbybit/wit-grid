Columns describe how row data is read, displayed, edited, filtered, and written back.

```tsx
import { Grid, type ColumnDef } from '@eregister/wit-grid-react';

type Person = {
	id: string;
	name: string;
	team: string;
	score: number;
};

const columns: ColumnDef<Person>[] = [
	{ field: 'name', header: 'Name', width: 180 },
	{ field: 'team', header: 'Team', width: 160 },
	{ field: 'score', header: 'Score', type: 'number', width: 120 },
];

export function PeopleGrid({ rows }: { rows: Person[] }) {
	return <Grid rows={rows} columns={columns} getRowId={(row) => row.id} />;
}
```

## Required Shape

Every column needs:

| Field    | Type     | Notes                                                                            |
| -------- | -------- | -------------------------------------------------------------------------------- |
| `field`  | `string` | Stable data path and column identity. Dot paths are supported for nested values. |
| `header` | `string` | Visible column header text.                                                      |

Use stable `field` values. They are used by state, events, filtering, sorting, selection ranges, clipboard, and persistence. Use `colId` only when the public API identity needs to differ from the row data path.

## Sizing And Visibility

```tsx
const columns = [
	{ field: 'name', header: 'Name', width: 220, minWidth: 140, maxWidth: 360 },
	{ field: 'internalNotes', header: 'Notes', hide: true },
	{ field: 'status', header: 'Status', pinned: 'left' },
];
```

`width` must be a positive finite number. `minWidth` and `maxWidth` constrain user resizing. `pinned` is an initial setting; use the grid API for runtime pin changes.

Users hide a column by dragging its header out of the grid (the drag preview reads **Hide** before they let go;
Escape cancels; the last visible column stays), from the sidebar's Columns panel, or with
`api.setColumnVisible(field, false)`. Turn the drag off with `dragOutHidesColumns={false}` (core:
`mountGridHost(api, el, { dragOutHidesColumns: false })`). A hidden column keeps its filter, which keeps filtering,
and a pinned column stays pinned: shown again, it is back in its lane.

## Values

By default, the grid reads `row[field]`. Dot paths read nested data.

```tsx
const columns = [{ field: 'account.owner.name', header: 'Owner' }];
```

Use `valueGetter` when display data is derived.

```tsx
const columns: ColumnDef<Person>[] = [
	{
		field: 'displayName',
		header: 'Display name',
		valueGetter: ({ row }) => `${row.name} (${row.team})`,
		valueGetterDependencies: ['name', 'team'],
	},
];
```

Use `valueFormatter` when the raw value should stay unchanged, but display/export text should be formatted.

```tsx
const columns: ColumnDef<Person>[] = [
	{
		field: 'score',
		header: 'Score',
		valueFormatter: ({ value }) => `${Number(value).toFixed(1)} pts`,
	},
];
```

## Writing Values

Use `valueSetter` to control edit commits.

```tsx
const columns: ColumnDef<Person>[] = [
	{
		field: 'score',
		header: 'Score',
		valueSetter: ({ row, value }) => {
			const next = Number(value);
			if (!Number.isFinite(next) || next < 0) return false;
			row.score = next;
			return true;
		},
	},
];
```

Return `false` to reject a commit. Return a promise when validation depends on asynchronous work. Call `abort()` for an immediate rollback.

## Column Types

Wit Grid ships these types in the grid core, usable by name with no registration:

| Type                            | Behavior                                                      |
| ------------------------------- | ------------------------------------------------------------- |
| `checkbox`                      | Checkbox; a press selects the cell and toggles the value.     |
| `date`, `datetime`              | Intl date (and time) display, with a calendar popover editor. |
| `number`, `currency`, `percent` | Intl number formats, right-aligned, with a stepper editor.    |
| `progress`, `rating`            | Progress bar with label; stars, click to rate.                |
| `url`, `email`                  | Links; only http, https and mailto become links.              |
| `tags`                          | Palette-coloured chips; type in the editor to create a tag.   |

The cells are DOM renderers and editors: no React work per cell, so they cost no more than plain text during
scroll. Their colours come from the grid theme (text, accent, popover tokens), so badges, chips and editor
popovers follow built-in and custom themes. Set `--og-ct-accent`, `--og-ct-radius` or `--og-ct-rating` on the
grid to adjust the cells alone.

Register types with options through the `columnTypes` grid prop.

```tsx
import { Grid, currencyColumnType, selectColumnType, comboboxColumnType } from '@eregister/wit-grid-react';

const columnTypes = {
	usd: currencyColumnType({ currency: 'USD' }),
	status: selectColumnType(
		[
			{ value: 'active', label: 'Active', color: 'emerald' },
			{ value: 'paused', label: 'Paused', color: 'amber' },
		],
		{ noneLabel: 'No status' }
	),
	team: comboboxColumnType([
		{ value: 'fe', label: 'Frontend', group: 'Engineering' },
		{ value: 'ui', label: 'UI Design', group: 'Design' },
	]),
};

const columns = [
	{ field: 'revenue', header: 'Revenue', type: 'usd' },
	{ field: 'status', header: 'Status', type: 'status' },
	{ field: 'team', header: 'Team', type: 'team' },
];

<Grid rows={rows} columns={columns} columnTypes={columnTypes} />;
```

Factories: `selectColumnType`, `multiSelectColumnType`, `comboboxColumnType`, `tagsColumnType`,
`personColumnType`, `numberColumnType`, `currencyColumnType`, `percentColumnType`, `dateColumnType`,
`dateTimeColumnType`, `progressColumnType`, `ratingColumnType`, `checkboxColumnType`, `urlColumnType` and
`emailColumnType`. Options are `{ value, label?, color?, icon?, description?, group?, disabled? }`, where
`color` is a palette name (`gray`, `red`, `amber`, `emerald`, `blue`, `violet`, `rose`…) or any CSS colour.
A type supplies `renderer`, `cellEditor`, `valueFormatter` and `filterDef`; whatever the column sets itself wins.

### More cell types

| Factory                                                    | Value                                             | Cell                                           | Editor                                                                 |
| ---------------------------------------------------------- | ------------------------------------------------- | ---------------------------------------------- | ---------------------------------------------------------------------- |
| `switchColumnType({ onLabel, offLabel })`                  | boolean (`'true'`, `1` keep shape)                | On / off switch, toggles on press              | Enter toggles                                                          |
| `segmentedColumnType(options)`                             | option value                                      | All options inline; one press picks            | Enter opens them as a list                                             |
| `colorColumnType({ swatches })`                            | `#rrggbb`                                         | Swatch and hex                                 | Palette (arrow keys), hex field, system picker, screen eyedropper      |
| `longTextColumnType({ lines, maxLength })`                 | string                                            | One to three clamped lines, full text on hover | Textarea popover: Enter adds a line, Ctrl / ⌘ + Enter saves            |
| `linkedRecordColumnType(records, { loadOptions, onOpen })` | record ids                                        | Record chips; pressing one calls `onOpen`      | Record picker (paged from your API with `loadOptions`)                 |
| `cascadeColumnType({ options \| loadChildren })`           | path `['in', 'ka', 'blr']` or `'in/ka/blr'`       | “India › Karnataka › Bengaluru”                | One column per level, ← → ↑ ↓ Enter, search across paths, async levels |
| `dateRangeColumnType({ presets })`                         | `{ start, end }`, `[start, end]` or `'start/end'` | “Mar 4 – 18, 2026” and its length              | Two-month range calendar with presets, Apply                           |
| `sparklineColumnType(options)`                             | numbers (array, `'1,2,3'`, `{ values }`)          | Line, area, bar or win / loss chart            | (display only)                                                         |

Sparklines take `type`, `color` or `colorBy: 'trend'`, `curve: 'smooth'`, `markers` (`last`, `minmax`, `all`),
`reference` (a value, `'average'` or `'zero'`), `label` (`last`, `change`), `format`, fixed `min` / `max` for
comparable rows, `height` and `strokeWidth`. They stretch to the column without measuring it and keep strokes
and markers crisp.

`cascadeColumnType` loads levels with `loadChildren(path, signal)` (mark leaves `isLeaf: true`), labels stored
paths with `resolvePath(path)`, and searches a server with `searchPaths(query, signal)`; `changeOnSelect` allows
picking a state as well as a city. Checkbox cells now toggle on Enter too.

### Options from a server

`selectColumnType`, `comboboxColumnType`, `multiSelectColumnType`, `tagsColumnType` and `personColumnType`
can load their options instead of listing them:

```tsx
const columnTypes = {
	account: comboboxColumnType([], {
		// One page of matches. Return `hasMore: false` (or a plain array) on the last page.
		loadOptions: async ({ search, offset, limit, signal, rowId }) => {
			const res = await fetch(`/api/accounts?q=${encodeURIComponent(search)}&offset=${offset}&limit=${limit}`, { signal });
			const { items, total } = await res.json();
			return { options: items.map((a) => ({ value: a.id, label: a.name, description: a.region })), hasMore: offset + limit < total, total };
		},
		// Labels for the values cells show before any list has loaded them (one batched call).
		resolveOptions: async (ids) => (await fetch(`/api/accounts?ids=${ids.join(',')}`).then((r) => r.json())).map(toOption),
		pageSize: 50,
	}),
};
```

- The editor searches on the server after a pause in typing (`debounceMs`, default 250) and from
  `minQueryLength` characters. One request is in flight at a time: a newer search waits for it, then the latest
  runs. Closing the editor aborts the page still loading (`signal`).
- The next page loads when the list is scrolled near its end, or when arrowing past the last option. The list
  shows a loading row, a Retry row when a page fails, and "50 of 1,204" when the loader returns `total`.
- Cells show a placeholder while `resolveOptions` looks a value up. Every option a page or lookup returns is
  remembered, so its label appears in cells, exports and filters.
- `rowId` and `colField` let options depend on the row (cities of the row's country, say).
- The column's filter lists the same options (loaded the same way), so filters and cells agree on labels.

The renderers and editors are also exported on their own (`createSelectRenderer`, `createSelectEditor`,
`createDateEditor`…) for use on a column directly: `renderer: { kind: 'dom', renderer }` and
`cellEditor: { kind: 'dom', editor }`. A `DomCellEditor` you write works the same way.

## Renderers And Editors

Use `renderer` to control cell display. Use `cellEditor` to control edit UI.

```tsx
const columns: ColumnDef<Person>[] = [
	{
		field: 'team',
		header: 'Team',
		renderer: { kind: 'react', component: TeamBadge },
		cellEditor: TeamEditor,
	},
];
```

Renderer specs support text, DOM, React, and imperative React modes. A DOM renderer's `mount()` and `update()`
receive the cell's `value`, `node`, `col`, state flags and the grid `api` — the same api React renderers get. For high-frequency cells, `capabilities.scroll` chooses between `'text'` (stand-in text while scrolling) and `'live'` (the real renderer, within a per-frame budget) — see [Renderer Capabilities](/docs/next/renderer-capabilities) for the tradeoff and when to use each.

## Filtering And Sorting

```tsx
const columns: ColumnDef<Person>[] = [
	{ field: 'name', header: 'Name', sortable: true }, // filters as text
	{ field: 'score', header: 'Score', sortable: true, filterDef: { type: 'number' } },
	{ field: 'team', header: 'Team', filterDef: { type: 'select' } },
	{ field: 'id', header: 'ID', filterDef: { type: 'none' } },
];
```

Column types choose a fitting filter on their own; `filterDef` overrides it. See [Filtering](/docs/next/filtering).

## Clipboard

Use `onCopy` and `onPaste` when clipboard text should not be the same as the raw cell value. See
[Clipboard](/docs/next/clipboard) for the grid-level copy/paste API and event payloads.

```tsx
const columns: ColumnDef<Person>[] = [
	{
		field: 'score',
		header: 'Score',
		onCopy: ({ value }) => String(value ?? ''),
		onPaste: ({ pastedText }) => Number(pastedText),
	},
];
```

## Header Groups

Group related columns under a shared spanning header label with `headerGroup`. Columns with the same label at
the same position are merged into one spanning header cell automatically — no separate registration step.

```tsx
const columns: ColumnDef<Person>[] = [
	{ field: 'name', header: 'Name', width: 160 },
	{ field: 'q1Revenue', header: 'Q1', headerGroup: 'Revenue', width: 100 },
	{ field: 'q2Revenue', header: 'Q2', headerGroup: 'Revenue', width: 100 },
	{ field: 'q1Cost', header: 'Q1', headerGroup: 'Costs', width: 100 },
	{ field: 'q2Cost', header: 'Q2', headerGroup: 'Costs', width: 100 },
];
```

<Callout title='Nesting groups' type='info'>
	`headerGroup` also accepts an array for nested group levels, outermost to innermost — `headerGroup: ['Financials', 'Revenue']` renders Financials
	&gt; Revenue &gt; the leaf column header. There is no separate `headerGroupLevel` field; the array's order **is** the nesting.
</Callout>

## Auto-sizing

Double-click a column's resize handle to auto-size it to fit its content. The same behavior is available
programmatically through `GridApi`:

```typescript
// Resize a single column to fit its widest cell (header included by default)
api.autoSizeColumn('price');

// Resize all visible columns at once
api.autoSizeAllColumns();

// With options
api.autoSizeColumn('name', { padding: 24, includeHeader: true });
api.autoSizeAllColumns({ padding: 16, minWidth: 60, maxWidth: 400 });
```

| Option          | Type      | Default | Description                                            |
| :-------------- | :-------- | :------ | :----------------------------------------------------- |
| `padding`       | `number`  | `16`    | Extra pixels added to the measured content width.      |
| `includeHeader` | `boolean` | `true`  | Include the header cell text in the width measurement. |
| `minWidth`      | `number`  | —       | Clamp the result to at least this many pixels.         |
| `maxWidth`      | `number`  | —       | Clamp the result to at most this many pixels.          |

`autoSizeAllColumns` accepts the same options and applies them uniformly to every visible column.

## Capabilities

Column capability callbacks allow per-cell or per-column rules.

```tsx
const columns: ColumnDef<Person>[] = [
	{
		field: 'score',
		header: 'Score',
		canEdit: ({ row }) => row.team !== 'Locked',
		canSort: () => true,
		canExport: () => true,
	},
];
```

Capability callbacks exist for editing, selection, copy, paste, grouping, fill, sort, filter, pin, resize, delete, expand, drag, column movement, and export.
