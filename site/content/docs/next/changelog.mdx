## `next` (unreleased)

### Added — sticky group headers, native, with options

Expanded group headers stick under the column header while their rows scroll, stack one per level, and are pushed up when their group ends. They use the browser's native sticky positioning, so a stuck header moves with the scroll on the GPU, with no JavaScript per frame. `grouping.stickyHeaders` takes `true` or `{ levels, shadow }` to cap how many levels stick or drop the shadow. A stuck header carries the class `og-row-group-stuck`. See [Sticky group headers](/docs/next/grouping#sticky-group-headers).

### Changed — pinned rows stay put natively

Rows pinned to the top or bottom (`pins: { top, bottom }`, `pinTopRows`, `pinBottomRows`) no longer move with JavaScript while scrolling. They stay in place on their own, so they no longer lag behind fast scrolls.

### Fixed — the selection box scrolls with the cells

The range selection box now moves with the cells it covers while you scroll.

### Changed — one group renderer API across display modes

Full-width group rows, the hierarchy cell and sticky headers are all drawn by the same renderer, with the same `GroupRenderContext`: `level`, `expanded`, `label`, `count`, `aggregates`, `isStuck`, and actions `toggle()`, `setExpanded()`, `expandAll()`, `collapseAll()` and `selectChildren()`. React gets `<GroupToggle>` and `<GroupCount>`; DOM renderers get `renderGroupToggle(ctx)`. See [One context for every group renderer](/docs/next/grouping#one-context-for-every-group-renderer).

**Breaking:** `grouping.rowRenderer` now receives a `GroupRenderContext`, and React group row components (`groupRowRenderer`, `totalRowRenderer`) receive that context as props instead of `{ visualRow, api }`. Read `ctx.row` for the row and `ctx.api` for the API.

### Fixed — column order is kept when the `columns` prop is replaced with equivalent columns

Passing a new `columns` array with the same columns no longer undoes a reorder the user made.

### Changed — two scroll choices for custom renderers: `text` and `live`

A custom renderer now picks one of two behaviors during scroll with `capabilities.scroll`. `'text'` (the React
default) shows stand-in text for cells entering view and mounts the renderer once scrolling settles. `'live'` (the
DOM default) mounts and updates the renderer during scroll within a per-frame budget; a cell over budget shows
stand-in text for that frame and is completed right after, so it is never blank. `scrollText` sets the stand-in
text. Grid-level tuning moves to one option, `rendererOptions.live`. HTML snapshots are removed. See
[Renderer Capabilities](/docs/next/renderer-capabilities).

**Breaking:** the old options are removed, with no deprecation period.

| Removed                                                                                                          | Use instead                                                |
| ---------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------- |
| `scrollPresentation: 'freeze'`                                                                                   | `scroll: 'text'` (the React default, so usually delete it) |
| `scrollPresentation: 'update'`                                                                                   | `scroll: 'live'` (the DOM default, so usually delete it)   |
| `scrollPresentation: 'live'`                                                                                     | `scroll: 'live'`                                           |
| `scrollPresentation: 'text-impostor'` + `textImpostor.render`                                                    | `scroll: 'text'` + `scrollText`                            |
| `scrollPresentation: 'html-snapshot'` + `htmlSnapshot`                                                           | `scroll: 'text'`; HTML snapshots no longer exist           |
| `live.update: 'imperative'`                                                                                      | renderer `kind: 'imperativeReact'`                         |
| `live.priority`, `live.allowEmergencyShell`                                                                      | none; over-budget cells always show stand-in text          |
| `rendererOptions.domUpdate.maxMsPerFrame`                                                                        | `rendererOptions.live.maxMsPerFrame`                       |
| `rendererOptions.liveReact` (overscan, mount and update limits)                                                  | `rendererOptions.live` (same names)                        |
| `rendererOptions.htmlSnapshot`, `rendererOptions.textImpostor`                                                   | none                                                       |
| render counters `htmlSnapshotHitsDuringScroll`, `htmlSnapshotMissesDuringScroll`, `textImpostorUsesDuringScroll` | none                                                       |

### Changed — one data-write API: `transaction`

`api.transaction({ rows, cells })` writes rows and cells together as one atomic change with one undo entry, and
`api.transaction(tx, { async: true })` queues it with other high-frequency writes and returns a promise.
`setRows` now diffs against the current rows, so only changed rows update. Row-level writes re-validate changed
and added rows after they commit, and removed rows drop their issues (`validation.validateOnTransaction`). See
[Transactions](/docs/next/transactions).

**Breaking:** the old write methods are removed, with no deprecation period.

| Removed                                  | Use instead                                                                    |
| ---------------------------------------- | ------------------------------------------------------------------------------ |
| `applyTransaction(tx)`                   | `transaction({ rows: tx })`; the row nodes are at `result.rows`                |
| `applyTransactionAsync(tx, callback)`    | `transaction({ rows: tx }, { async: true }).then(callback)`                    |
| `flushAsyncTransactions()`               | `flushTransactions()`                                                          |
| `batchCellValues(updates, source)`       | `transaction({ cells: updates, source })`                                      |
| `batchCellValuesAsync(updates, source)`  | `transaction({ cells: updates, source }, { async: true })`                     |
| `setCellValueAsync(rowId, field, value)` | `transaction({ cells: [{ rowId, colField: field, value }] }, { async: true })` |
| `updateRows(fn)`                         | `setRows(fn(api.rows().getAll()))`                                             |
| `transaction({ rowTransaction })`        | `transaction({ rows })`                                                        |
| `transaction({ rows: allRows })`         | `setRows(allRows)`                                                             |
| type `BatchCellValueUpdate`              | `GridCellWrite`                                                                |

### Added — DOM cell renderers receive the grid `api`

`mount()` and `update()` get `api`, the same object React cell renderers receive, so DOM cells can select cells
and write values.

### Changed — built-in `number`, `date` and `checkbox` cells render without React

The built-in column types use DOM renderers with the same markup and styles. The React components are still
exported.

### Changed — text cells are lighter, and long values end in an ellipsis

Cell text is laid out as a block, so `text-overflow: ellipsis` now applies (long values were cut off without one).
Cells of columns without a custom renderer hold their text directly, one element per cell, which cuts the layout
work of vertical scrolling by about a third. See [Migration Notes](/docs/next/migration-notes) if your CSS targets
`.og-cell-content`.

### Changed — custom renderer cells have one box fewer

The portal host inside a custom-renderer cell is now `display: contents`: the renderer's container lays out directly
in the cell. This cut layout time for grids with custom DOM renderers by about 12%. See
[Migration Notes](/docs/next/migration-notes) if your CSS styles `.og-cell-portal-host`.

### Fixed — rendering limits no longer hide visible rows or columns

When `runtimeLimits` bound the rendering window, rows at the bottom and columns on the right of the viewport could
be left blank. The limit now trims overscan and keeps everything in view.

### Fixed — scrolling in steps kept restarting the scroll session

Each discrete scroll — an instant wheel tick, a scripted `scrollTop` assignment — fires its own `scrollend`, and the
grid ended its scroll session on each one: the scroll-end work re-ran between steps, every row was restyled twice
per step, and `overscanAdaptive` never took effect. The session now ends once 50 ms pass without movement after the
browser reports the end.

### Fixed — header indicators restyled on every horizontal scroll frame

The sort indicator's inline style was rewritten (to the same value) for every visible header cell on every frame of
a horizontal scroll. Header indicators are now written only when they change.

### Fixed — `runtimeLimitsClamped` render counter

It was counted but always reported as 0.
